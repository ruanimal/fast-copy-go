# Fast Copy 详细文档

[返回中文 README](../README.md) · [English README](../README.en.md)

使用 [mygo](https://github.com/egoist/mygo) 原生 UI 与 [onevra](https://github.com/oneo-me/onevra) 组件库构建的 Linux / macOS 文件复制工具。项目参考 [FastCopy 官方帮助](https://fastcopy.jp/help/fastcopy_eng.htm) 中的同盘批量读写、异盘并行读写与校验设计。

## 运行

需要 Go 1.27.3 或更新版本，以及 Linux 图形桌面或 macOS。首次构建需要网络下载 Go 模块。

```sh
go run .
```

使用 `go build -o fastcopy .` 构建当前平台的可执行文件。Linux 需要 mygo 支持的图形环境及相应运行时库；macOS 需要在桌面会话中运行。

Linux 和 macOS 使用应用绘制的居中标题栏，支持拖动窗口；Linux 提供最小化、最大化和关闭按钮，macOS 保留系统窗口控制。Linux 窗口装饰仍受桌面环境和合成器的具体行为影响。

交叉构建示例：

```sh
CGO_ENABLED=0 GOOS=darwin GOARCH=arm64 go build -o fastcopy-macos-arm64 .
CGO_ENABLED=0 GOOS=darwin GOARCH=amd64 go build -o fastcopy-macos-amd64 .
```

## 打包与发布

项目通过 `go.mod` 固定与依赖版本一致的 MyGo CLI，可直接使用 `go tool mygo`，首次运行需要下载 Go 模块。`assets/icon.svg` 是图标源文件，`assets/icon.png` 是打包及窗口使用的 1024×1024 PNG；修改图标后需要同时更新 PNG：

```sh
go tool mygo build -platform linux/amd64,linux/arm64
# 在 macOS 上运行，以生成 DMG
go tool mygo build -platform darwin/amd64,darwin/arm64
```

默认版本号在 `mygo.json`，产物位于 `dist/`。Linux 提供 `.deb`、`.rpm` 和含 `install.sh` 的 `.tar.gz`；安装脚本将应用安装到当前用户的 `~/.local`。Linux 包含桌面菜单入口和图标，依赖 GTK 3；在 Debian/Ubuntu 上可用 `sudo apt install ./包名.deb` 安装。macOS 生成 `.app` 和 `.dmg`；当前使用临时签名，未使用 Apple Developer ID 签名或公证，其他 Mac 的 Gatekeeper 可能阻止打开。跨平台构建不会生成 macOS DMG，必须在 macOS 上打包。

CI 在 Linux 和 macOS 运行格式检查、`go vet`、竞争检测及两个架构的打包，并保留短期构建产物。推送如 `v1.2.3` 或 `v1.2.3-rc.1` 的 Git 标签会触发发布，标签去掉 `v` 后作为包版本；带预发布后缀的标签创建预发布版本。发布附带各平台安装包和 `SHA256SUMS`，可用 `sha256sum -c --ignore-missing SHA256SUMS` 校验已下载的文件。发布需要仓库允许 GitHub Actions 使用 `contents: write` 创建 Release；推送标签前应确认对应提交已通过 CI。

## 使用

选择或输入一个或多个来源（每行一个）和一个已有的目标文件夹。路径中的首尾空格会保留，但界面暂不支持路径中包含换行符。来源以其原文件名放入目标文件夹，目录会合并。默认复制大小或修改时间不同的文件；也可以选择覆盖、跳过已有文件、仅覆盖较旧文件或只读校验。任务可暂停、继续或取消；暂停在当前 I/O 系统调用结束后生效，取消不会撤销已经完成的文件。任务结束后显示平均复制速度：以成功提交的普通文件逻辑大小除以总耗时，耗时包含扫描、校验和暂停；跳过或失败的文件不计入。稀疏文件和硬链接按逻辑大小计入，因此该速度并不等于物理磁盘写入速度。

可从文件管理器将文件或文件夹拖入或复制后粘贴到来源输入框，多个路径会逐行追加；将一个已有文件夹拖入或粘贴到目标输入框即可设置目标。普通文本仍按文本编辑方式粘贴。目标文件夹检查在后台进行，检查期间不能启动任务。任务运行时不接受拖入。

点击目标文件夹输入框或右侧箭头可显示最近使用的 7 个目录，最近使用的排在最前；输入文字可筛选历史，也可以直接输入新路径；在未筛选的历史列表中选择“清除历史记录”可删除所有历史，而不改变当前目标。启动任务并确认目标文件夹有效后记入历史。历史会保存在用户配置目录的 `fastcopy-go/destination-history.json` 中，重新启动应用后仍可使用；暂时离线的目录也会保留。

任务进行中的“处理速度”约每半秒更新，按最近约 3 秒内完成的逻辑处理量计算；采样区间内没有进度上报时显示“暂无进度”。正在进行的 I/O 在完成前无法计入，稀疏文件空洞和保留的硬链接也计入逻辑进度，因此该速度不等于物理磁盘吞吐量。窗口平滑可减少分块造成的跳动，但也会让速度变化显示得稍慢。

默认使用 xxHash3 校验，可切换 SHA-256、SHA-512、SHA3-256、SHA3-512、SHA-1 或 MD5；也可选择复制后重读来源。xxHash3 适合快速检查，防篡改用途应选用 SHA-256 或更强的加密散列。可选保留普通文件、符号链接和新建目录的扩展属性、ACL，或保留普通文件硬链接；无法保留所选属性时会报错，不会静默声称成功。符号链接按链接本身复制，不跟随目标。

界面默认使用简体中文，可在“高级设置”的“语言”中切换为 English；切换立即生效并自动保存，重新启动后仍会使用所选语言。

主窗口提供包含和排除过滤输入框，多个规则用分号分隔。点击“高级设置”可配置文件属性、校验及 I/O 参数；修改立即生效，关闭弹窗或按 Esc 不会撤销修改。无效的 I/O 参数会显示提示，并阻止任务启动；任务运行时不能更改这些设置。

Linux 可选“优先目标直接写入”：来源可以普通读取到程序的有界对齐缓冲区，目标单独尝试 `O_DIRECT`，不同设备模式继续并行预读；跨文件批处理在来源支持时也可能使用直接读取。目标未报告对齐信息时，仅对内核 exFAT 文件系统按文件系统块大小和内存页大小保守对齐并尝试；首次直接写入遭拒绝时会清空私有暂存文件并回退普通 I/O，开始写入后的错误则停止当前文件，不替换已有目标。稀疏文件仍使用保留空洞的路径。该模式可能减少目标页缓存占用，但不保证更快；校验读取仍可能使用缓存。

普通文件先写入目标目录下私有临时目录中的文件，写入完成、同步并通过可选校验后才重命名替换目标。复制失败或取消时清理当前临时文件。跳过模式使用平台原子不覆盖操作，防止任务运行期间新出现的目标被覆盖。已完成的文件不会回滚；运行过程中其他程序修改来源或目标时，不保证快照语义。普通文件权限、修改时间以及符号链接的修改时间会被保留；已有目录不会被改写权限或扩展属性。特殊文件、路径中间的目标符号链接目录不受支持。

## 复制策略与平台差异

- **同盘**：连续的普通文件先读入同一个有界内存批次，再依次写入；批次默认最多 32 MiB、8192 个文件，避免每个小文件都在读取和写入间切换。单个超过批次的文件、稀疏文件及需要处理的硬链接使用各自的路径；当前不会把大文件尾部与下一个文件拼进同一批次。校验线程可能与后续写入并发，同盘场景仍会产生读写竞争。
- **不同设备 / SSD**：使用两个可复用的 2 MiB 缓冲区并行读取与写入。数据写入后可立即开始下一个文件，前一个文件由独立校验工作器处理。
- **自动**：Linux 尝试从 sysfs 识别物理块设备及旋转介质；虚拟设备、网络文件系统等无法可靠判断时保守使用同盘策略。macOS 当前也保守使用同盘策略；如确定为 SSD 或不同设备，可手动选择并行模式。
- **缓存控制**：Linux 当文件系统报告了直接 I/O 的对齐要求时尝试 `O_DIRECT`，并处理非对齐的文件尾部；无法确认对齐要求或不支持时回退到普通 I/O，界面中的 I/O 状态提示会显示具体回退原因。普通 I/O 是否经过缓存还取决于文件系统和挂载选项，例如 SMB 的 `cache=none`。Linux 在来源读取后及目标文件同步后建议内核回收相应缓存，类似 `nocache` 的目标，但这种建议不保证立即回收，也不等于始终绕过页缓存。macOS 尝试 `F_NOCACHE`，失败时回退。校验读取在 Linux 上使用普通 I/O 并提示内核回收缓存。
- 可以选择预分配；Linux 使用 `fallocate`，macOS 使用 `F_PREALLOCATE`。不支持时回退，疑似稀疏文件不会预分配。
- **稀疏文件**：当来源文件系统支持 `SEEK_DATA` / `SEEK_HOLE` 时，只写入数据区并保留空洞；不支持区段查询时回退为普通复制，因此目标可能占用更多磁盘空间。
- Linux 的异设备直接 I/O 在内核支持时使用原生 AIO，同时提交当前块写入与下一块读取；初始化或首个读取不受支持时回退到 Go 读写流水线。其他路径使用 Go goroutine 或同步 I/O；macOS 尚无原生异步 I/O 队列，也没有性能等价保证。

Linux 使用 POSIX ACL 扩展属性；macOS 的 ACL 与扩展属性通过系统 `copyfile` 接口复制。macOS 的符号链接 ACL 可用性依赖文件系统，相关复制行为仍需在更多真实设备上验证。已有目录的 ACL 和扩展属性不会被覆盖。

启用复制后校验时，写完的文件进入独立的有界校验队列，最多三个文件处于待校验或待提交状态；主流程只在校验成功后提交临时文件。取消或校验失败时会清理未提交文件，不会替换其原有目标；如果文件系统拒绝清理，隐藏暂存目录可能残留。启用硬链接保留时，依赖已提交目标的链接会先等待相关校验完成。独立“仅校验”操作按文件顺序执行。

高级设置中的选项以及主窗口的操作、已存在文件处理方式和读写策略会在更改后自动保存到用户配置目录的 `fastcopy-go/preferences.json`，重新启动后恢复；无效或未完成的 I/O 参数也会保留并继续提示修正。高级设置可调整单次 I/O 大小、同盘缓冲及修改时间比较容差。可选“遇错继续”：记录扫描或单项处理错误并继续其他项目，结束后通过“查看错误”查看详情；非法选项、冲突来源、目标位于来源内部等整体安全校验仍会立即停止。

包含／排除过滤支持以分号分隔的 `*`、`?`、字符类；以 `/` 开头从来源的父目录起匹配，以 `/` 结尾匹配目录，其余规则匹配路径尾部。目录排除会跳过其整个子树。若同时设置文件和目录包含规则，文件需匹配文件规则并位于匹配的目录中。示例：包含 `*.txt;照片/` 且排除 `缓存/`。这里实现的是常用相对路径规则，不保证覆盖 FastCopy 所有过滤语法和高级时间、大小过滤。

这仍不是完整的 FastCopy 功能等效实现：同步、移动、删除、自动文件系统时间精度检测、所有目标文件系统上的稀疏洞保证、资源流的完整语义等能力尚未实现或验证。扩展属性复制可能因为目标文件系统或权限而失败。macOS 发布版已在 Apple Silicon 桌面上启动并检查界面，复制行为和不同存储设备仍需进一步验证；Linux 的真实设备和文件系统覆盖也尚不完整。

```sh
go test -race ./...
go vet ./...
# 在待测文件系统上运行基准（会创建临时数据）
TMPDIR=/path/to/test-volume go test -run '^$' -bench BenchmarkCopyStrategies ./internal/copyengine
```

上面的基准使用 32 MiB 文件且不启用校验；另有 `BenchmarkCopySmallFiles` 用于带校验的小文件测试。基准结果依赖设备、文件系统和缓存状态，不能代表 FastCopy 的性能。Linux 直接 I/O 测试需要支持 `STATX_DIOALIGN` 的文件系统；测试临时目录在不支持该能力的 tmpfs 上时会验证回退，并跳过直接 I/O 部分。可将 `TMPDIR` 设到支持直接 I/O 的文件系统上运行该测试。
